# PowerQuota v1.7.0 Release Notes

## Accurate, Self-Healing Claude Quotas

### Summary
PowerQuota v1.7.0 fixes two bugs affecting Claude Code quota tracking: a 5-hour quota number that could be wildly wrong compared to the official Claude app, and Claude quota going stale until a manual re-login.

---

### Key Features & Improvements
- **Fixed Claude Code 5-hour quota mismatch**: The 5-hour ("session") quota parser labeled every session-scoped entry from Anthropic's usage API the same and kept only the first one, so when the API returned a per-model limit alongside the "all models" aggregate, the aggregate could be silently dropped in favor of the barely-used per-model number — showing, for example, 1% used locally when the official app showed 32%. Session parsing is now scope-aware like weekly parsing already was, keeping both as separate windows and always surfacing the aggregate in the headline display. (#45, #46)
- **Fixed stale Claude quota after token expiry**: `ClaudeProvider` had no token-refresh logic, unlike the Codex and Gemini providers — once an access token was cached, a 401 just failed instead of retrying with a fresh token, so Claude quota stopped updating until you manually ran `/login` and refreshed. PowerQuota now reads the refresh token from Claude Code's credentials file, proactively refreshes near expiry, and reactively refreshes on a 401, matching the existing Codex/Gemini behavior. (#48, #49)
