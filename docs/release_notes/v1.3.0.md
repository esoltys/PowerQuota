# v1.3.0

A major stability and capability release introducing expanded GitHub Copilot auto-detection, dynamic OpenAI / Codex quota window resolution, resilient Dock band management, non-blocking asynchronous auto-refresh intervals, deterministic resource cleanup, and crash-safe configuration persistence.

### ⚡ Copilot & Codex Enhancements
- **GitHub Copilot Token Auto-Detection**: automatically scan and detect Copilot credentials across local developer environments (VS Code auth tokens, CLI configurations, and host sessions), with enhanced snapshot quota parsing for dynamic headers and multi-model accounts ([#11](https://github.com/esoltys/PowerQuota/pull/11)).
- **Dynamic Codex Window Resolution**: dynamically resolve window labels and descriptions for monthly, weekly, and sliding session quotas, providing accurate reset countdowns and limit tracking ([#12](https://github.com/esoltys/PowerQuota/pull/12)).
- **Codex Quota Resilience**: handle quota exhaustion edge cases, negative/zero balances, and sliding-window rate limit throttling gracefully without dropping cards ([#21](https://github.com/esoltys/PowerQuota/pull/21)).

### 🎛️ Dock & Command Palette Integration
- **Dock Band Stability & Duplicate Prevention**: eliminated duplicate Dock bands and ensured stable command item registration across Command Palette reload cycles ([#21](https://github.com/esoltys/PowerQuota/pull/21)).
- **Orphaned Band ID Cleanup**: automatically prune stale and orphaned Dock band IDs from Command Palette settings on extension reload (`reload.ps1`) ([#21](https://github.com/esoltys/PowerQuota/pull/21)).
- **Immediate Account Removal**: immediately remove deleted accounts from the active runtime state and Dock views without requiring an app reload or restart ([#15](https://github.com/esoltys/PowerQuota/issues/15), [#29](https://github.com/esoltys/PowerQuota/pull/29)).

### 🔄 Engine, Refresh & Concurrency
- **Synchronized Refresh Serialization**: serialized background and manual quota refresh operations with locking to eliminate shared-state race conditions and prevent duplicate in-flight HTTP requests ([#13](https://github.com/esoltys/PowerQuota/issues/13), [#26](https://github.com/esoltys/PowerQuota/pull/26)).
- **Dynamic Auto-Refresh Interval Updates**: apply auto-refresh timer changes immediately in real-time when changed in Settings without needing to restart the extension ([#14](https://github.com/esoltys/PowerQuota/issues/14), [#28](https://github.com/esoltys/PowerQuota/pull/28)).

### 🛠️ Architecture & Reliability
- **Crash-Safe Configuration Persistence**: synchronized configuration access and atomic file writes prevent config corruption during unexpected shutdowns or rapid saves ([#18](https://github.com/esoltys/PowerQuota/issues/18), [#23](https://github.com/esoltys/PowerQuota/pull/23)).
- **Deterministic HTTP Resource Disposal**: properly dispose HTTP request and response streams across all provider integrations to eliminate socket and memory leaks ([#17](https://github.com/esoltys/PowerQuota/issues/17), [#24](https://github.com/esoltys/PowerQuota/pull/24)).
- **Preserved HttpClient Lifecycle**: retain caller-owned `HttpClient` instances upon service disposal to avoid invalidating shared client connections ([#16](https://github.com/esoltys/PowerQuota/issues/16), [#27](https://github.com/esoltys/PowerQuota/pull/27)).
- **Non-Fatal Fresh Install Diagnostics**: make diagnostic logging initialization non-fatal on fresh installs and locked directory scenarios ([#19](https://github.com/esoltys/PowerQuota/issues/19), [#22](https://github.com/esoltys/PowerQuota/pull/22)).
- **Isolated Test Architecture**: fully decoupled unit and integration tests from production user config files and Windows Credential Vault storage ([#20](https://github.com/esoltys/PowerQuota/issues/20), [#25](https://github.com/esoltys/PowerQuota/pull/25)).
