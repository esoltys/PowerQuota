# PowerQuota v1.10.0 Release Notes

## Claude Reliability & Extra Usage Display

### Summary
PowerQuota v1.10.0 fixes a bug where a rate-limited Claude account got stuck showing a frozen cooldown message instead of usage data, and cleans up the Claude extra usage display.

---

### Key Features & Improvements
- **Fixed frozen rate-limit cooldown and desktop-cache fallback**: A 429 from Claude's usage endpoint threw straight past the Desktop-cache fallback (only wired up for 401/403), so a rate-limited account showed "API Rate Limit Cooldown • Rate limited, retrying in 60s" indefinitely instead of falling back to Claude Desktop's cached usage data. The countdown was also baked into a static string at the moment of failure and never ticked down. `ClaudeProvider` now falls back to the Desktop cache on a 429 just like 401/403, the cooldown message is now computed live from `RetryAfter`, and a cached sample older than its own window's duration (5h session, 7d weekly) is now rejected as too stale rather than shown as current — the remaining windows report how long ago the cache was last updated. (#70, #71)
- **Fixed MSIX manifest validation for 3-part `-Version`**: `build-msix.ps1 -ForStore -Bundle -Version X.Y.Z` (the repo's own 3-part version convention) failed MakeAppx with "The package manifest is not valid", because the manifest and bundle manifest require exactly 4 numeric parts. The script now pads a 3-part version to 4 parts for the manifest while keeping artifact filenames as passed. (#67)
- **Cleaned up the Claude extra usage row**: The extra usage row used a bank icon instead of the Claude provider icon, and showed a verbose `Extra Usage: {used} / {monthly_limit} {currency}` label where the `monthly_limit` came from an API field that doesn't reflect the account's actual configured cap. The row now uses the Claude icon and a shorter `{used} {currency} extra` label with the misleading limit dropped. (#72)
